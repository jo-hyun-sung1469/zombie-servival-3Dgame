# Unity 코드 리뷰

## 원칙
- 기본은 **읽기 전용**이다. 사용자가 요청하기 전에는 파일을 수정하거나 커밋하지 않는다.
- 추측이 아니라 코드에서 확인한 것만 지적한다. 확신이 없으면 "확인 필요"로 표시한다.
- 스타일 취향이 아니라 버그, 성능, 유지보수 위험을 우선한다.

## 1. 리뷰 범위 정하기
- 특별한 지정이 없으면 현재 브랜치와 기준 브랜치의 차이를 본다: `git diff <base>...HEAD` (base 기본 `main`).
- 커밋 전 변경이면 `git diff`와 `git diff --staged`를 본다.
- PR 번호가 주어지면 `gh pr diff <번호>`를 사용한다.
- diff가 크면 `.cs` 로직 변경을 먼저 보고, 씬/프리팹/에셋은 변경 여부와 위험만 확인한다.

## 2. 체크리스트

**정확성**
- 파괴된 `UnityEngine.Object`에 대한 `?.`/`??` 사용, 널 참조 가능성
- 이벤트/델리게이트 구독 후 해제 누락 (`OnEnable`/`OnDisable` 비대칭)
- 코루틴이 비활성/파괴된 오브젝트에서 끊기는 문제, 중복 실행
- `async/await`에서 취소 처리 누락, Unity API의 메인 스레드 외 호출
- 초기화 순서 의존(`Awake`/`Start`/`OnEnable`) 문제

**성능**
- `Update` 계열의 `GetComponent`/`Find*`/할당/`Debug.Log`/`Instantiate`/`Destroy`
- LINQ, 문자열 연결, 박싱으로 인한 GC
- 불필요한 매 프레임 연산 (이벤트 기반으로 전환 가능한지)

**직렬화와 에셋**
- 직렬화 필드 이름 변경 시 `FormerlySerializedAs` 없음 -> 씬/프리팹 값 유실
- 새/이동/삭제된 에셋의 `.meta` 누락 또는 단독 변경, GUID 충돌 가능성
- 씬/프리팹 대규모 변경으로 인한 머지 충돌 위험, 프리팹 오버라이드 실수
- `ProjectSettings`, 패키지 매니페스트의 의도치 않은 변경

**설계**
- 한 클래스의 책임 과다, 순환 참조, 싱글톤 남용
- asmdef 경계 위반, 에디터 전용 코드가 런타임에 섞임 (`#if UNITY_EDITOR` 누락)

**멀티플레이/서버 (해당하는 경우)**
- 서버 검증 없이 클라이언트 값을 신뢰하는 코드 (치트 위험)
- 프레임레이트 의존 로직, 직렬화 구조 변경으로 인한 호환성 문제

**테스트**
- 변경된 로직에 대한 테스트 존재 여부, 재현 가능한 확인 방법

## 3. 출력 형식
```
## 리뷰 요약
(변경 목적 이해 + 전체 판단 2~3줄)

## 발견 사항
### [Blocker] 제목
- 위치: 파일:라인
- 문제: 무엇이 왜 문제인지
- 제안: 수정 방향 (필요하면 짧은 코드 예시)

### [Major] / [Minor] / [Nit] ...

## 확인이 필요한 점
- 코드만으로 판단할 수 없는 부분

## 결론
Approve / Approve with comments / Request changes 중 하나와 이유
```
- 심각도: **Blocker**(머지 불가: 크래시, 데이터 유실, 보안), **Major**(꼭 고쳐야 함: 명확한 버그, 심각한 성능), **Minor**(개선 권장), **Nit**(취향).
- 발견 사항이 없으면 억지로 만들지 말고 검토한 범위와 함께 그렇게 말한다.
- 발견 사항은 중요도 순으로 정렬하고, 같은 유형은 묶어서 보고한다.
- 사용자가 원하면 수정 사항을 반영한다.
